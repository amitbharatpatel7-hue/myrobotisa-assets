# Robot Care (Supabase edge functions)

Source of three edge functions on project `vxnestmhtjotidhzzqbo`. Deployed with the Supabase MCP `deploy_edge_function`;
each bundle is flat, so the shared files are copied beside its `index.ts`:

| Function | verify_jwt | Bundle |
|---|---|---|
| `robot-care` (the GitHub App's webhook; GET = the App's slug and permissions) | off (GitHub signs it) | `index.ts`, `handler.js`, `core.js`, `clients.js` |
| `robot-care-accept` (members area: Accept fix, Not now, sync) | on | `../robot-care-accept/index.ts`, `accept.js`, `core.js`, `clients.js` |
| `robot-care-ask` (members area: Ask a question) | on | `../robot-care-ask/index.ts`, `accept.js`, `core.js`, `clients.js`, `ask_email.js` |

`ask_email.js` is generated by `build_ask_email.py` from `ops/lms_email.py`; re-run it after a theme change.
The table changes are `ops/supabase/2026-10-28-robot-care-fixes.sql` (hub DECISIONS D25 stage 1).

Tests (no network):

    node test/accept_sim.mjs     # fix path, Accept fix, Not now, sync, Ask a question, every refusal
    node test/wire_test.mjs      # the exact GitHub and Supabase requests
    node test/members_card.mjs   # the members-area card in Chromium, against a local Postgres mirror (needs root + Postgres 16)

The App (`my-robot-i-s-a-robot-care`) has Contents and Pull requests write, Issues write, Actions read. It has no Checks
or Commit statuses permission, so Accept fix judges checks by the pull request's `mergeable_state` ("clean" = every
check passed); with those two permissions added it reads each check by name instead.
